## 1. 上游基线

| 项 | 值 |
|---|---|
| 子模块 | `third_party/OrcaSlicer`，remote `https://github.com/wzx011011/OrcaSlicer.git` |
| 对照基准 | 官方 OrcaSlicer `main` |
| 当前 pin | `0a3724ed2f106dd40b8a6b6f89c6a83a546cc81c`（2026-09-11） |
| 子模块状态 | 保持上游原样，不提交本地改动；OWzx 的改动全部以补丁形式放在本仓库 |

规则：

1. "与上游一致"一律指上面这个 pin。升级 pin 时先更新本节，再在追踪文档里登记受影响的任务。
2. 某项行为如果取自其他提交、分支或补丁，必须在对应任务里写明来源。
3. Creality Print（官方开源，AGPL-3.0）只作为局域网协议和创想云接入的参考实现，不是行为真值。

## 2. 引擎补丁

`cmake/ApplyOrcaSlicerPatches.cmake` 在 configure 时按文件名顺序把 `patches/orcaslicer/*.patch` 应用到子模块工作树。应用后的状态（补丁指纹 + 子模块 `git diff` 哈希）记录在 `build/` 中；子模块被还原或补丁有变动时，只要改动都在补丁涉及的文件内，就自动还原这些文件并重新应用，其余文件有改动则 configure 报错。补丁文件是 configure 依赖，修改后会自动重新配置。

| 补丁 | 文件 | 目的 |
|---|---|---|
| 0001 | `Config.hpp` | 枚举选项缺少 keys_map 时不崩溃 |
| 0002, 0003 | `MeshBoolean.cpp` | 兼容 CGAL 5.4 的补洞接口 |
| 0004, 0006 | `GCode/GCodeProcessor.cpp` | filament map 越界检查；MSVC lambda 捕获 |
| 0005 | `Fill/FillRectilinear.cpp` | MSVC lambda 捕获 |
| 0007 | `Emboss.cpp` | 字体注册表 wstring 越界读 |
| 0008 | `CSGMesh/CSGMesh.hpp` | GCC 缺 include |
| 0009 | `PrintConfig.cpp/.hpp` | Creality Print 项目方言：`multicolor_method` 配置定义 |
| 0010 | `Brim.cpp` | 多挤出机 filament map 下标夹取 |
| 0011 | `PrintObjectSlice.cpp` | MMU 分段的挤出机与层维度边界 |
| 0012 | `GCode/ToolOrdering.cpp` | filament map 下标夹取 |
| 0013 | `GCode.cpp` | Creality Print 项目方言：最大冲刷次数提到 8 |
| 0014 | `GCode/WipeTower2.cpp` | 单工具 prime 下溢 |
| 0015 | `Format/bbs_3mf.cpp`、`Model.hpp` | 共享网格的多个体共用凸包（加载提速） |
| 0016 | `GCode/OrderingStrategies.cpp` | TSP 去交叉迭代改为工作量上限：约 84 点以内与上游完全一致，更大的路径限制总扫描量，避免退化输入卡死 |

0004、0010–0012、0014 是引擎侧的防御性夹取。GUI 侧已按上游 `full_fff_config` 为每个耗材槽组装逐耗材向量（2026-11-03），这些夹取不再是唯一防线。
