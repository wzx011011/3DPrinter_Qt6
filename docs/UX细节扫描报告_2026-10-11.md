**总体结论**：反馈基建比预期成熟——统一 toast 栈、ConfirmDialog 全覆盖、切片/校准/发送进度条、空状态、参数 tooltip 主路径（真数据从上游 schema 灌入）、ConfigWizard、最近文件、undo 命令族大半都已到位。真正的高收益缺口集中在三类：**① 服务层已建好但没接到 UI 的基础设施；② 误导用户的错误信息；③ GUI 线程冻结点**。

## 第一梯队：高收益低成本（→ 计划 M1.5 批 U1-U7）

**1. 失败通知显示成"绿色成功"（最该先修）→ U1** — `BackendContext.h:48` 中 `NotiSuccess = 1`，但 `BackendContext.cpp` 有 6 处失败路径把 severity 传成 1（如 :1089 "Project backup failed"、:1164 "Config import failed"）。结果同一条失败同时渲染成**绿色成功 toast** + 琥珀警告横幅（`ErrorToast.qml:128` 按 1 染成功色），色彩语义自相矛盾。改 6 个枚举实参即可。

**2. 偏好页快捷键表在教用户按出危险操作 → U2（= M11 提前）** — `PreferencesPage.qml:476` 写"克隆选中 Ctrl+D"，实际 Ctrl+K 才是克隆、**Ctrl+D 是删除全部**（`main.qml:539`）——用户照表按键会直接触发清盘确认框。另有 W/E/R（真 M/R/S）、平放 G（真 F）、切割 Ctrl+Shift+X（真 C）、←/→ 跳 100 步（真：普通步进 1）共 6 处矛盾，且缺 Ctrl+R/G/K/Tab 整套。此项属已知 M11（Q11 批次），本次确认未修且误导性最高，提前单独修——纯数据改动，Q11 执行时对应子项核销。

**3. 取消能力对用户不存在 → U3** — 服务层 `cancelSlice` / `cancelExport`（SliceService）实现完备，**全 QML 零调用**；切片进度 toast 加一个"取消"按钮就把现成能力接上。同理 3MF 导入：`ProjectServiceMock.cpp:1062` 的 `loadProgressUpdated` 进度信号 + :1785 的 `cancelLoad` 都已实现，QML 完全没消费——大文件导入时用户只见白等。

**4. 全应用没有忙碌光标 → U4** — 全 src 无一处 WaitCursor/BusyCursor；切片、导入、排布期间界面无任何"在忙"信号（唯一光标变化是盘图标 hover 手型）。一处 `setOverrideCursor`（或全局遮罩）覆盖所有长操作。

**5. 双击 .3mf 打不开文件 → U5** — `main_qml.cpp:192-234` 命令行只认 `--open-page` 等测试参数，位置参数被静默忽略。桌面切片软件的文件关联是基本盘；`applyStartupOpenRequests` 的 plumbing 已存在，加位置参数转发即可。

**6. 拖 .gcode 进窗口被静默丢弃 → U6** — 拖放白名单（`main.qml:302`）不含 .gcode，而 Ctrl+I 对话框支持它；顺带给拖入不支持文件的情况加个 toast（目前也是静默）。

**7. 快捷键文档有幽灵条目 → U7** — KBShortcutsDialog.qml 宣称 Ctrl+方向键相机平移、Space 呼出命令面板、"?" 显示快捷键表、Ctrl+Shift+E/Ctrl+M，全部无实现。要么补实现（Space 呼出命令面板和 "?" 打开快捷键表都是便宜活——CommandPalette/KBShortcutsDialog 组件均已存在）要么删条目。

## 第二梯队：高收益中成本（→ 计划 M2 增补 U8-U14）

**8. GUI 线程冻结点 → U8 / U13**
- **保存/自动备份是同步写盘 → U8**：`ProjectServiceMock.cpp:11168/1648` 在 GUI 线程写 3MF（含每盘缩略图），大工程 Ctrl+S 冻结数秒；更糟的是 `BackendContext.cpp:223` 的 autoSave 定时器周期性调用它——**用户不操作也会周期性掉帧**。建议移 worker（加载路径已有同款模式可抄）。
- **arrange 排布同步阻塞**：`ProjectServiceMock.cpp:4730` 同步跑 `Slic3r::arrangement`，无进度无取消（→ U9 一并入 undo 时评估移 worker）。
- **`main.qml:177` exportModel 同步导出 → U13**：大模型导出冻结窗口（SliceService 里的导出 worker 反而是好的，没复用）。
- **AiAgentService.cpp:110-114 stop() 阻塞 wait → U13**、**EditorViewModel.cpp:10424-10428 processEvents 忙等 → U13**（= 现代化报告 P2 项）。
- 预览 GUI 线程全量解析已由 M0 的 P1 直传解决（73-75ms），不在本批。

**9. 三个最常用操作不可撤销 → U9** — 自动排布 A（`EditorViewModel.cpp:10670`）、自动摆向 Q（:7611）、单对象拆分（:7650）都没 push undo 命令，按了回不去；`SceneSnapshotCommand` 现成，`splitSelectedToObjects`(:8311) 就是照抄模板。导入/拖放是否入栈也需验证（:8392 未见 push）。

**10. 文本框内 Ctrl+Z/Ctrl+A 被窗口级 Shortcut 抢走 → U10** — `textEditHoldFocus` 只保护了 Tab（`main.qml:622`）。

**11. 真实发送打印链路是黑盒 → U11（接真链路 X1 前就该修好的 UX）** — 三连：FTPS 上传 `uploadProgress` 信号零订阅（`FtpUploader.cpp:51`，大 gcode 上传无进度无剩余时间）；上传失败只 qDebug 无任何提示（`DeviceServiceMock.cpp:758`）；上传中再点打印会 fall-through 到 mock 造成双打印状态（:843-860）。最刺眼的是 MQTT publish 失败仅打日志却**无条件把设备置为"printing"**（:747-755）——用户看到打印中，打印机什么都没收到。

**12. 关键信息不可复制 → U12** — 统计面板（StatsPanel.qml）、坐标 tooltip、错误 toast 全是纯 Text 不可选中。报障求助时错误信息抄不下来。给 ErrorToast 加"复制详情"、StatsPanel 改可选中文本即可。

**13. Prepare 页信息密度 → U14** — 对象数/成本/预计耗时只有切到预览页才能看到（StatsPanel），上游是侧栏常驻 SlicedInfo；StatusBar.qml 是死文件（M19 处置）。
