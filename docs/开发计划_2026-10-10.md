## 0. 执行方式：动态工作流逐里程碑推进

- **形态**：每个里程碑一个 workflow run，串行流水线（唯一构建目录 `build/` 的项目规则排除了并行 worktree 方案）。
- **每项节奏**：实施员（读规格→实现→git commit）→ verify 门禁（`auto_verify_with_vcvars.ps1`，确定性退出码，失败喂回实施员，每项最多 3 轮）→ bench 门禁（触及性能路径的项加跑 `run_stage_bench.ps1`，按 `docs/perf-baseline.md` 稳定锚点规则判定回退 ≤~10%）→ 根治复核员（独立上下文读 diff，对照审计条目"为什么不是补丁"意图）。
- **失败隔离**：单项 3 轮仍红 → 标记 blocked 跳过；同文件域的依赖项随之跳过，独立项继续。
- **提交纪律**：每子项一提交，conventional commits 风格；只 `git add` 本项改动文件（工作树常驻他人未提交 WIP 与用户自行删除的文档，严禁 `git add -A`）。
- **运行约束**：verify 会全机杀 cmake/ninja/link（Q4 修复前）——run 期间请勿手动构建；run 出错用 AmendWorkflow 修订续跑（未变项零成本缓存）。
- **验收口径**：Q13a 落地前按"9 阻塞套件全绿 + 脚本 exit 0"判定（审计报告 ④ 章引言口径说明）；转阻塞后升为全量。
- **与运行中工作流的和解（2026-10-12 审查裁定）**：另一会话的 dwfrun-4faf5a30（旧 24 条目脚本）已按旧脚本收口 M1（Q7-Q12+Q13b+P2 七项 done，见 §7）；其 M2 核心五项（Q14/Q1/Q5/Q6/Q11）与本计划等价零浪费，且已带"Q1/Q5/Q6 合批 verify"执行裁定（保留）。路由 = **M1 收口后由规划会话 AmendWorkflow 注入新序列**（编辑 `.zcode/workflow-drafts/M1-M4-剩余里程碑全量执行.dwf.ts` 后以 path 提交，已完成步骤缓存保留零重跑；注入时尊重在途 M2 子项的缓存边界），此后原会话不再改编该 run。注入序列 = M1.5（U1→U3→U4→U5→U6→U7→U2）→ M2 核心（Q14→Q1∥Q5∥Q6∥Q11）→ P4 → U8-U14 → M2.5（G2-G5）→ M3（含 S8）→ M4（两并行道）。注入前严禁并行起第二个 run（唯一构建目录 + verify 全机杀构建进程的既有教训）。**注入已执行（2026-10-12）**：Q13b 尾巴随 e4b56b1 落地后，AmendWorkflow 完成，新 run = **dwfrun-de8f628d**（38 条目：M1.5 七项 / M2 五项含合批 / P4 / U8-U14 / M2.5 四门 / M3 八项含 S8 / M4 六项含 X6；基线日志改名 m15_* 强制实跑）。**当前暂停（2026-10-12 用户指示）**：基线 verify 绿（实测 6m27s，增量门禁远快于预估）→ U1 实施中被停，零提交落库、工作树干净；恢复 = ResumeWorkflowRun 原样续跑，或按用户对 verify 策略（全逐项 vs 风险分层）的决策 AmendWorkflow 后续跑。

## 1. 全局规则（贯穿所有里程碑）

1. 唯一构建：`powershell -ExecutionPolicy Bypass -File scripts/auto_verify_with_vcvars.ps1`；**凡改 C++/QML 源码、测试或构建脚本必跑**（AGENTS.md 自测常备规则，非可选）。
2. 触及模型加载 / meshData / 场景展开 / 拾取 / 切片 / 预览解析 / 渲染提交路径的项，加跑 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/perf/run_stage_bench.ps1`；稳定锚点相对 `docs/perf-baseline.md` 回退 ≤~10%，易变指标按该文档噪声规则判定。
3. 触及切片链路（SliceService / PreviewViewModel / EditorViewModel / `src/cli/*` / 两个 ServiceMock / 子模块指针 / PerfBench / 门禁文件）会自动触发切片回归门禁（正确性 + 效率双层；**P4 落地后增加第三层"步骤画像"**，见 §6d），属预期成本。
4. WIP 文件（RhiViewport / RhiViewportRenderer / CameraController 等）相关项一律排在 Q2 收尾提交之后。
5. 行为对齐上游（third_party/OrcaSlicer 为真值）；颜色归品牌自有（2026-10-07 裁定）。
6. **Qt 底座目标 = 6.12 LTS**（M2.5 切换前为 6.10）：切换前的新代码避免引入 6.12 已弃用 API；S8 的 qmlcachegen/qmllint 规则集以 6.12 为准（故 S8 排 M2.5 后）；Qt 锚点三处（auto_verify:241 / CMakeLists:109 / tag-build.yml:60）切换时一并更新，禁止只改一处留下双版本混链。

### 判定口径

- **步骤键**：`model_prep, config_prep, param_apply, validate, mesh_slicing, perimeters, infill_regions, infill_toolpath, z_contouring, support, overhang_lift, skirt_brim, path_optimization, gcode_export`（+`unknown_*` 兜底键——上游同步改了引擎文本时门禁会红，用 `-UpdateBaseline` 重建，这是特性不是缺陷）。

### 实施与验证步骤

1. gen_benchmark_models.py 移植塔生成器，本地生成并单独切一次，确认 support 步骤占大头（画像合理性目验）。

5. 负向：篡改基线某步骤值 → 期望 exit 2 且复测路径生效；恢复基线。
6. 完整 canonical verify（门禁自触发）→ 12 套件 0 failed + 门禁绿 + step_profiles 报告可见。
