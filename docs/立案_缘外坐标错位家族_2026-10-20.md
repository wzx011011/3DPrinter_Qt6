# 立案：缘外渲染/坐标错位家族（2026-10-20 会话）

## 案件背景

多盘目验（item 13）触发：mp_demo.3mf 双盘场景加载后准备页视口背景整片变红
`(192,48,0)`（上游 ERROR_BG_LIGHT 的量化桶），盘 2 上对象不可见。此前 2026-10-10
已有同类记录："x > bedWidth 的四边形无像素"（PrepareSceneData.cpp:1067-1072
的图标列内贴 workaround 即其产物）。

## 今日破案链（方法可复用）

1. **像素桶背景检测**：`//16*16` 量化后 Counter 对比 shot1(深)/shot2(红)，
   1.02M 像素整片替换 → 排除局部绘制，锁定 clearColor 路径。
2. **qWarning 失灵教训**：`/subsystem:windows` 无控制台时 Qt 默认消息走
   OutputDebugString，重定向 stderr 收不到（仅启动 banner 例外）。**探针必须
   用 `fprintf(stderr)+fflush`**，否则结论是假的"代码没跑"。
3. **fprintf 双探针**（recompute 入口 + clearColor 决策点）拿运行时真值：
   `plateCount=2 bed=300x300 origin=(0,-300) inst box=[-66.7,-63.2]...`
   —— 床矩形与实例包围盒坐标系不一致，一锤定音。

## 根因（两个，均已修）

### R1: meshData 归一化硬编码 220 床中心（主犯）

`ProjectService.cpp` meshData 生成尾部的 "plate normalization"：

```cpp
const float offsetX = 110.0f - centerX;   // 220/2 硬编码
const float offsetZ = -110.0f - centerZ;
```

把**全部盘的对象联合包围盒**整体平移到 (110,-110)。后果：
- 任何非 220 床（默认预置 K1 Max 300）整体偏 40mm；
- 多盘场景联合盒跨多盘，居中到盘 0 中心后，盘 2+ 的对象被拖进盘间空隙
  → 判"盘外" → 红底 + 红对象泡红底不可见。

**修复**：中心随真实床/网格推导（单盘 220 精确还原旧行为）：
`gridCenterX=((cols-1)*strideX+W)/2`、`gridCenterZ=-((rows-1)*strideY+D)/2`，
数据取自 `m_plateList`。修复后双盘各归各位、红底消失（截图
shot_fix1.png / shot_click.png 留档 build/）。

### R2: setPlateContext 不重算 outside 状态（从犯）

`PrepareSceneData::setPlateContext` 更新 plateCount 并重建床几何，但从不调
`recomputeOutsideState`。加载时序：模型批先到（此刻盘数还是 1）→ 判定按单盘
→ 盘数变 2 → 床面重画但 outside 判定永驻旧值。历史上"不红"其实是**判定从未
随多盘刷新**（shot1 的深底是漏判，不是正确）。R1 修复暴露 R2，两者叠加才完整。

**修复**：plateCount 变化时在 setPlateContext 内补 `recomputeOutsideState()`。

## 与 2026-10-10"缘外无像素"旧案的关系

同一坐标错位家族的强嫌疑：图标列/贴缘四边形当时"顶点正确、上传正确、无像素"，
而对象集实际被 R1 平移出真实盘区后，任何依赖 bed-extent 与 mesh 流对齐的
光栅化路径都可能表现异常。**旧案重启时第一动作**：在 R1/R2 修复后的二进制上
复测（还原 PrepareSceneData.cpp:1067 的外贴上游位置），大概率已消失或转性。
