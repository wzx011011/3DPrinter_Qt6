# CrealityPrint 依赖与协议边界审计

> 更新日期：2026-03-10
> 上游真值基线：见 [docs/源码真值基线.md](源码真值基线.md)
> 用途：梳理上游源码中的闭源依赖、动态库、云服务和协议边界，给后续 Qt6 迁移提供明确的范围控制。

## 结论摘要

上游 CrealityPrint 并非一个“全部可直接迁移”的纯开源 GUI 层。源码中已经明确存在以下边界：

- 闭源或非自由扩展：`bambu_networking` 插件及其相关能力
- 外部运行时依赖：WebView2、媒体播放、系统动态库
- 外部协议与服务：MQTT、SSDP、HTTP、云端登录、设备绑定、模型商城、上传/通知链路
- 平台相关媒体与 Web 宿主：`wxMediaCtrl2`、`PrinterWebView`、`WebViewDialog`、`BambuPlayer`

因此，后续迁移必须将这些能力分成三类：

1. 直连迁移：开源且可在 Qt6 中直接替代或复用
2. 包装适配：开源宿主可迁，但依赖闭源库、外部服务或专有协议
3. 暂缓或受限：当前不宜承诺“完全复刻”，需要单独兼容策略

## 证据清单

### 1. 闭源网络插件

关键证据：

- `third_party/CrealityPrint/src/slic3r/Utils/bambu_networking.hpp`
  - 定义 `BAMBU_NETWORK_LIBRARY "bambu_networking"`
  - 暴露用户登录、设备连接、消息、HTTP 错误、打印任务、FTP、MQTT、通知等接口与错误码
- `third_party/CrealityPrint/src/slic3r/Utils/NetworkAgent.cpp`
  - 使用 `LoadLibrary` / `dlopen` 动态加载网络模块
  - 通过函数指针绑定 `bambu_network_*` 系列接口
- `third_party/CrealityPrint/README.md`
  - 明确写明 `bambu networking plugin is based on non-free libraries from Bambulab`

边界判断：

- 该模块不能被简单视为“纯开源源码的一部分”。
- Qt6 迁移时不应承诺对其内部实现做源码级还原。
- 最合理策略是“包装适配”而不是“重写替代”。

建议策略：`包装适配`

---

### 2. 设备通信与协议栈

关键证据：

- `third_party/CrealityPrint/src/CMakeLists.txt`
  - 依赖 `PahoMqttCpp`
- `third_party/CrealityPrint/src/slic3r/Utils/NetworkAgent.hpp`
  - 暴露 SSDP、打印机连接、消息订阅、HTTP 错误等回调
- `third_party/CrealityPrint/src/slic3r/Utils/bambu_networking.hpp`
  - 明确包含 MQTT、FTP、云通知、上传、绑定等错误码与参数
- `third_party/CrealityPrint/src/slic3r/Utils/Bonjour.cpp`
  - 存在局域网发现逻辑
- `third_party/CrealityPrint/src/slic3r/GUI/print_manage/*`
  - 设备管理与多机管理相关实现集中在此目录

边界判断：

- 局域网发现、MQTT、HTTP 和上传链路是强外部依赖。
- 即便接口层开源，最终行为仍受外部设备协议和服务器接口约束。

建议策略：

- 局域网发现与设备基础连接：`直连迁移` 或 `包装适配`
- 云端任务、上传、通知、绑定：`包装适配`
- 未公开协议细节的扩展能力：`暂缓或受限`

---

### 3. Web 容器与登录体系

关键证据：

- `third_party/CrealityPrint/src/slic3r/CMakeLists.txt`
  - 包含 `GUI/WebViewDialog.cpp/.hpp`
  - 包含 `GUI/PrinterWebView.cpp/.hpp`
  - 包含 `GUI/OAuthDialog.cpp/.hpp` 与 `GUI/Jobs/OAuthJob.*`
  - Windows 安装中包含 `MicrosoftEdgeWebView2RuntimeInstallerX64.exe`
- `third_party/CrealityPrint/src/slic3r/GUI/ModelMall.*`
- `third_party/CrealityPrint/src/slic3r/GUI/WebUserLoginDialog.*`
- `third_party/CrealityPrint/src/slic3r/GUI/LoginDialog.*`

边界判断：

- GUI 宿主本身可迁移到 Qt WebEngine 或等价容器。
- 但登录、商城、OAuth、设备 Web 内容仍依赖外部 Web 服务和认证流程。

建议策略：

- Web 容器宿主：`直连迁移`
- OAuth / 登录 / 商城后端交互：`包装适配`
- 任何未公开鉴权流程：`暂缓或受限`

---

### 4. 媒体与摄像头播放

关键证据：

- `third_party/CrealityPrint/src/slic3r/CMakeLists.txt`
  - 包含 `GUI/wxMediaCtrl2.cpp/.h` 或 macOS 对应实现
- `third_party/CrealityPrint/src/slic3r/GUI/CameraPopup.*`
- `third_party/CrealityPrint/src/slic3r/GUI/CameraUtils.*`
- `third_party/CrealityPrint/src/slic3r/GUI/MediaPlayCtrl.*`
- `third_party/CrealityPrint/src/slic3r/GUI/BambuPlayer/*`

边界判断：

- 媒体宿主和播放器 UI 可以迁到 Qt Multimedia 或其他播放器内核。
- 但具体视频流协议、鉴权方式、设备端媒体通道可能仍依赖专有实现。

建议策略：

- 本地媒体宿主与 UI：`直连迁移`
- 摄像头流、设备媒体协议：`包装适配`
- 某些深度依赖 BambuPlayer 的路径：`暂缓或受限`

---

### 5. 平台运行时与系统动态库

关键证据：

- `third_party/CrealityPrint/src/CrealityPrint_app_msvc.cpp`
  - 使用 `LoadLibraryExW` 加载 `opengl32.dll` 等运行时
- `third_party/CrealityPrint/src/StackWalker.cpp`
  - 动态加载 `psapi.dll`
- `third_party/CrealityPrint/src/hidapi/*`
  - Windows、Linux、macOS 上均存在 `LoadLibrary` / `dlopen` 使用

边界判断：

- 这些主要是平台运行时依赖，不属于业务闭源边界。
- Qt6 迁移需要关注可替代性和打包方式，但不构成产品功能范围问题。

建议策略：`直连迁移`

## 对 Qt6 迁移的直接影响

1. `P5 Device / Monitor / Network` 不能再被当成普通 UI 重构任务，它首先是协议与插件边界任务。
2. `P6 Model Mall / WebView / 登录` 也不是纯页面迁移，必须先走 Web 容器和认证依赖审计。
3. `P2/P3/P4` 仍然是最适合优先推进的模块，因为它们大部分属于开源可控范围。
4. 后续若承诺“完全还原”，必须明确区分：
   - GUI 宿主完全还原
   - 依赖外部闭源插件的能力通过包装接入
   - 未开放协议的能力只能受限承接

---

## 当前建议

1. 将 `P5` 前置增加“网络与插件适配层”子任务，不直接跳到设备页 UI 细化。
2. 将 `P6` 前置增加“Web 容器 / 登录宿主 / 商城依赖边界”子任务。
3. 在后续任务拆解中，把下列模块统一标记为“高风险迁移模块”：
   - `NetworkAgent` / `bambu_networking`
   - `print_manage/*`
   - `PrinterWebView` / `WebViewDialog` / `OAuthDialog`
   - `CameraPopup` / `wxMediaCtrl2` / `BambuPlayer`

## 结论

`P0.3` 所需的闭源依赖、动态库、云服务与协议边界已经完成首轮审计，可以作为后续任务拆分和范围控制依据。
