## Task 2: Delete-plate instance migration in PartPlateList::deletePlate (B2)

**Goal:** Deleting a plate must migrate its instance memberships instead of
dropping them (fixes orphaned objects).

**Upstream truth:** `PartPlateList::delete_plate` keeps the deleted plate's
instances and merges them into the next plate ("keep its instance at origin
position and add them into next plate if have") —
`third_party/OrcaSlicer/src/slic3r/GUI/PartPlate.cpp:3710-3761`. Read those
lines first and mirror the merge semantics.

**Current bug:** `src/core/model/PartPlateList.cpp:50-63` — `deletePlate`
erases the plate and silently drops its `m_obj_to_instance_set` entries.

**Implementation (src/core/model/PartPlateList.cpp, deletePlate):**

1. Before erase, capture the target plate's membership set
   (`PartPlate::objToInstanceSet()`, `PartPlate.h:191-196`).
2. Destination plate: the NEXT plate after deletion (same index position);
   when deleting the LAST plate, the PREVIOUS plate. (Guard: plateCount() > 1
   is already enforced.)
3. Insert each captured `(objIdx, instIdx)` pair into the destination plate's
   membership (use the plate's add-instance path so state stays consistent);
   do not carry over `m_instance_outside_set` entries as outside — instances
   are re-homed wholesale. Read upstream 3710-3761 and match it if it says
   otherwise.
4. Keep existing behavior for current-plate clamping, reindex,
   `updatePlateCols()` / `updatePlateOrigins()`. Destination plate readiness
   re-evaluation (updateSliceReadiness) must run via the membership-add path.

**Tests (tests/PartPlateTests.cpp — extend existing patterns):**

- Deleting a middle plate migrates its instances to the next plate
  (`findInstance` returns the new plate index for every migrated pair).
- Deleting the last plate merges instances into the previous plate.
- Rejection of old behavior: after delete, no previously-assigned instance has
  `findInstance == -1` (no orphans).
- Current-plate index stays valid; plate count/grid updates unchanged.

**Verify:** canonical build exit 0; PartPlateTests green; atomic commit
`fix(plates): migrate instance memberships to next plate on delete (upstream PartPlate.cpp:3710)`.

## Task 3: Plate-switch slicing guard (B1) + all-plates print/export readiness gates (B3)

**Goal:** Refuse plate switching while a slice is running, and gate
print/export-all-plates actions on upstream-equivalent aggregate readiness.

### B1 — Plate-switch guard during slicing

**Upstream truth:** `BackgroundSlicingProcess::can_switch_print()` returns
false while `STATE_RUNNING`
(`third_party/OrcaSlicer/src/slic3r/GUI/BackgroundSlicingProcess.cpp:140-155`);
plate switch gates the slice-context/preview swap on it
(`GUI/Plater.cpp:13879`).

**Implementation:**

1. `SliceService` (`src/core/services/SliceService.{h,cpp}`): add
   `Q_INVOKABLE bool canSwitchPlate() const` returning `!slicing()` (the
   `slicing` property already exists, `SliceService.h:136`). Semantics match
   upstream: refuse only while a slice is RUNNING.
2. Enforce in `EditorViewModel::setCurrentPlateIndex`
   (`src/core/viewmodels/EditorViewModel.cpp:7349`): early-return `false` when
   `sliceService_ && !sliceService_->canSwitchPlate()`, before any state
   mutation. Surface the refusal through the existing lightweight mechanism if
   one fits (e.g. a status/notification call already used by sibling guards);
   otherwise a plain `false` return matching current patterns is acceptable.
3. Rationale (do not deviate): `EditorViewModel::setCurrentPlateIndex` is the
   single QML entry point, so guarding there covers every QML path. The
   internal `projectService_->setCurrentPlateIndex` call sites
   (~lines 5390, 6902, 6925, 6987) are programmatic flows that must keep
   working mid/post-slice — do NOT enforce inside
   `ProjectServiceMock::setCurrentPlateIndex`.

**Test:** `tests/ViewModelSmokeTests.cpp` (existing pattern:
`EditorViewModel editor(&project, &slice);` e.g. line 588). Cover:
switch allowed when idle; switch refused while slicing (drive SliceService
into running state the same way existing tests at ~line 481 manipulate
`SliceService::sliceState`; if no seam exists to simulate a running slice,
unit-test the `canSwitchPlate()` predicate truth table instead and note the
one-line VM guard as review-verified — report honestly which was done).

### B3 — Print/export all-plates readiness gates

**Upstream truth** (`third_party/OrcaSlicer/src/slic3r/GUI/PartPlate.cpp`,
gating at `GUI/MainFrame.cpp:1372-1392`):

- `is_all_slice_results_valid` (:4989-4997) — ALL plates' slice results valid.
- `is_all_slice_results_ready_for_print` (:5000-5019) — every non-empty plate
  with printable instances must be print-ready AND at least one ready.
- `is_all_slice_result_ready_for_export` (:5022-5044) — additionally requires
  `has_printable_instances` on ready plates.

**Implementation:**

1. Add aggregate queries on `PartPlateList` (next to
   `isAllPlatesReadyForSlice`, `PartPlateList.h:154`):
   `isAllSliceResultsValid()`, `isAllSliceResultsReadyForPrint()`,
   `isAllSliceResultReadyForExport()`. Map upstream predicates onto existing
   per-plate state: `sliceResultValid()` (`PartPlate.h:175`),
   `isPrintable()` (:169), membership/`empty()` (:250). Read upstream
   4989-5044 first and match predicate logic exactly.
2. Do NOT change `isAllPlatesReadyForSlice` — its any-plate semantics already
   match upstream `is_all_plates_ready_for_slice` (:5047-5055).
3. Expose to the VM layer following the P055b passthrough pattern
   (`ProjectServiceMock.h:222-223` style) as needed.
4. Wire fail-closed gates into the export/print entry points:
   `SliceService::exportAllPlateGCodeToDirectory` (`SliceService.h:204`),
   `ProjectServiceMock::exportGcode3mf` (`ProjectServiceMock.h:700`), and the
   `EditorViewModel` call sites (~`EditorViewModel.cpp:8543`, `:8828`): export
   requires export-ready; print requires print-ready. On refusal return
   `false` and report via the existing error/notification path. Gate the
   action entry points only; do not redesign QML enablement.

**Tests (tests/PartPlateTests.cpp):** truth tables for the three aggregates —
all-plates-valid; empty plates skipped; zero-ready plates -> false; export
variant requires printable instances on ready plates; single-plate edge cases.

**Verify:** canonical build exit 0; full ctest run green (at minimum
PartPlateTests + ViewModelSmokeTests); atomic commit
`feat(slicing): plate-switch guard while slicing + upstream print/export all-plates readiness gates`.
