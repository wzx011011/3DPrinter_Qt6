## Source Truth and Required Metadata

`third_party/OrcaSlicer/src/slic3r/GUI/Tab.cpp:2005` defines the FFF Process
workspace. `TabPrint::build()` creates these Process pages in this order:

1. `Quality`
2. `Strength`
3. `Speed`
4. `Support`
5. `Multimaterial`
6. `Others`

The page-to-group relationship comes from the ordered
`add_options_page()` and `new_optgroup()` calls in that method, not from
`ConfigOptionDef::category`. For example, `Quality` contains Layer height,
Line width, Seam, Precision, Ironing, Wall generator, Walls and surfaces,
Bridging, and Overhangs; `Speed` contains Initial layer speed, Other layers
speed, Overhang speed, Travel speed, Acceleration, Jerk(XY), and Advanced.

The current Qt metadata is close enough to reuse, but is not source-correct:

- `SettingsDialog.qml` hard-codes eight Process tabs, including `Base`,
  `Cooling`, and `Retraction`, and uses `Other` rather than upstream `Others`.
- `ConfigOptionModel::pageNames()` has the same obsolete order and labels.
- `kPrintPageGroupMap()` intentionally moves Prime tower and other
  Multimaterial options into `Others`. That is not the upstream page map.
- `groupNames()`, `countForGroup()`, and `dirtyCountForGroup()` are global and
  sorted. They cannot distinguish same-name groups such as `Advanced` on
  different pages or preserve upstream group order.

Make the ordered `TabPrint::build()` page/group manifest the single Qt source
for Process navigation. Keep key-to-page/group lookup for each loaded option,
but add page-qualified, ordered queries such as page groups, visible count,
and dirty count. Group identity must be `(page, group)`, never group title
alone. Loaded keys not present in that manifest must be surfaced as an audited
mapping gap, not silently relocated by a category fallback.

The `Multimaterial` page is source truth, but this milestone must not create
H2C/A2L, multi-nozzle, or per-extruder editors. Its page and groups may only
show options whose existing scalar Process path is valid. Controls requiring a
multi-extruder UI remain out of scope rather than receiving a fake editor.

## Interaction Contract

The dialog should use this deterministic projection:

```text
selected print preset values
  -> ConfigViewModel.filterOptionIndices(print, query, advancedMode)
  -> ConfigOptionModel.filterIndicesByPage(indices, activePage)
  -> ordered page-qualified groups from TabPrint manifest
  -> each group header plus its visible option rows
```

- A group header toggles its own `page + group` collapse id. The glyph must
  reflect actual state and the whole header must be keyboard and pointer
  reachable; a static `+` is invalid.
- Collapse state survives page changes, query edits, and advanced-mode changes
  for the life of the dialog. It need not be persisted outside the dialog.
- A non-empty search temporarily reveals matching groups without mutating their
  saved collapse ids. Clearing search restores the prior collapsed state.
- Empty groups are not rendered. Counts are derived after the current
  tier/search/mode/page filter; dirty counts use the same page-qualified group
  identity but are not reduced by a search query.
- `ConfigOptionMode` behavior remains source-derived: simple mode shows mode
  zero; advanced mode is a superset including advanced/develop options. Do not
  implement a separate QML visibility rule.

Upstream has page/tree expansion in `Tab::set_expanded()` but no per-
`ConfigOptionsGroup` accordion state in `OptionsGroup.cpp`; group headers are
static. The requested group collapse is therefore an explicitly scoped OWzx
navigation enhancement. It must preserve upstream page, option, mode, and
preset semantics and must not be represented as existing upstream behavior.

## Dense Row Contract

Reuse existing `OptionRow` data and controls:

- `optSidetext()` is the primary unit. `optUnit()` is only a fallback.
- `valueSourceForKey()`, `optNullable()`, `optReadonly()`, `optIsDirty()`,
  `optTooltip()`, and the existing compact `CxBadge` lane supply source,
  inheritance, readonly, dirty, and help states.
- Add an accessible per-option reset action only when the option is dirty and
  writable, routed to the existing reset path. Add a group reset action only
  when that page-qualified group has dirty rows, routed to
  `ConfigViewModel::resetGroup()` after it is made page-aware where necessary.
- Numeric validation belongs in `ConfigOptionModel`, using existing upstream
  type/min/max/enum metadata. The QML field can show the returned error state,
  but must not be the sole validator. Do not present schema `optMax` as a
  second editable range value: the current `rangeCluster` has no paired-value
  model and is misleading for scalar options.
- `isVector` currently means a vector schema type but `extractDefault()` and
  `setValue()` expose only element zero. Keep a clear non-editing vector
  affordance or scalar-context explanation; do not add a vector editor in this
  milestone. A real vector editor changes per-extruder behavior and is out of
  scope.

## Reuse and Boundaries

Do not add a `ProcessSettingsService`, a parallel QML option model, QSettings
persistence for accordion state, JavaScript copies of preset values, or a new
package. Use an inline `ProcessGroupHeader` component in `SettingsDialog.qml`
or one small QML presentation component; do not keep group-header layout in an
individual `OptionRow` because a collapsed group contains no option row to
host it.

Do not add or expand:

- H2C/A2L, multi-nozzle, per-extruder, AMS, device, cloud, network, camera, or
  printer/material workflows.
- SLA Process behavior.
- New slicer logic, modified `libslic3r` algorithms, or unmapped cross-option
  auto-corrections. Upstream `Tab::on_value_change()` contains such behavior;
  port one only in a separately mapped behavior task, not as cosmetic UI
  validation.
- A fake value-chain reset or fake compatibility result. Reuse
  `ConfigViewModel` and `PresetServiceMock` only.
