# v5.11 Process Settings Source-Truth Convergence Summary

**Scope:** FFF Process (`print`) tier of `SettingsDialog` only.

## Executive Decision

v5.11 must replace the current flat, adjacent-row-derived Process list with an
ordered, source-mapped group projection. The reported `+` is broken because it
is decorative: `SettingsDialog.qml:500-524` derives a header from neighboring
option rows and `OptionRow.qml:143-188` renders no interactive state. This is
not an icon-only defect. Correct behavior needs first-class, page-qualified
group records after filtering, with an explicit expanded/collapsed state.

Use locked OrcaSlicer `TabPrint::build()` as the hierarchy truth
(`third_party/OrcaSlicer/src/slic3r/GUI/Tab.cpp:2005-2376`). The canonical
Process page order is `Quality`, `Strength`, `Speed`, `Support`,
`Multimaterial`, and `Others`. Replace the divergent hard-coded Process tabs
in `src/qml_gui/dialogs/SettingsDialog.qml:75-84`; do not retain `Base`,
`Cooling`, `Retraction`, or singular `Other` as Process pages. An option absent
from the page/group manifest is a mapping failure to audit, never an option to
move through an alphabetical or category fallback.

The implementation should reuse the existing effective-value and preset path:
`OptionRow -> ConfigOptionModel::setValue -> ConfigViewModel ->
sliceAffectingConfigChanged`. `ConfigOptionModel` remains schema/type/metadata
truth, and `ConfigViewModel` remains preset, dirty, source, reset, compatibility,
save-guard, and slice-invalidation truth. No new preset service, option store,
network dependency, package, or CMake-wide architecture is justified.

## Key Findings

- Existing data capability is stronger than the UI. `ConfigOptionModel` already
  loads `print_config_def` metadata and exposes page/group, mode, unit/sidetext,
  tooltip, dirty, reference, read-only, nullable, and vector state
  (`src/qml_gui/Models/ConfigOptionModel.cpp:381-560, 988-1612`).
- Existing C++ filtering is the single authority for search and modes:
  `ConfigViewModel::filterOptionIndices` makes Advanced a superset of Simple
  (`src/core/viewmodels/ConfigViewModel.cpp:1231-1288`). QML must not recreate
  that rule.
- Existing preset behavior is real and must remain on its current route: dirty
  guards, Save As for read-only presets, compatibility messages, hierarchy merge,
  reset, and slice invalidation are already owned by `ConfigViewModel` and
  `PresetServiceMock`.
- Current group APIs are insufficient for the new UI because global sorted group
  names cannot preserve upstream order or distinguish duplicate names such as
  `Advanced` on different pages. Group identity is always `(page, group)`.
- `GroupNavSidebar.qml` is a removed prototype and must stay out of `qml.qrc`.
  Restore group navigation through the Process projection and headers, not by
  reviving an obsolete parallel sidebar.
- Screenshot evidence establishes the compact, line-oriented settings geometry,
  but there is no dedicated Process dialog reference image. Visual details need
  runtime proof at the fixed dialog size rather than invention.

## Resolved Research Decisions

| Question | Decision for v5.11 | Reason |
|---|---|---|
| Who owns collapse state? | A new Process-only C++ presentation model owns session-only collapse keys. | It prevents QML delegate/cache drift while keeping the state out of presets, projects, and `QSettings`. |
| How long does it live? | It survives page, search, mode, edit, reset, preset switch, and dialog hide/show while the application presentation model exists. It is cleared only when that model is recreated. | This satisfies the requested workflow without undocumented persistent preferences. |
| How is a group identified? | Stable untranslated `(page, group)` technical IDs, for example a delimiter-joined key. | Labels can be localized and `Advanced` can occur on more than one page. |
| What does search do? | v5.11 remains active-page search: filter by query and mode, then active page, then ordered group partition. Matching rows in a collapsed group are temporarily revealed without changing its saved collapse bit. | This reconciles the reports: no hidden matches within the active page, but no unscoped global search/navigation redesign. A cross-page result navigator is future work and needs its own `Tab::activate_option` mapping. |
| Do we restore the old group sidebar? | No. | The historical QML audit intentionally keeps it unregistered; a first-class header/projection is sufficient and avoids two inconsistent navigation surfaces. |
| What validation is in scope? | C++ schema validation for the edited Process value is required: supported type, bounds, enum, read-only, and a user-visible result. Port dependency/availability behavior only where an exact `ConfigManipulation` rule is mapped and tested; do not add cross-option auto-correction. | This retains source truth and avoids inventing a QML rule matrix or broad slicer behavior. |
| How does reset work? | Per-option and group reset call the existing C++ route and use page-qualified group identity. Reset means return to the existing effective reference, not an unimplemented raw-override deletion. | `PresetServiceMock` lacks a raw-versus-resolved override contract. |
| How are vectors handled? | Show the supported scalar projection and explicit vector limitation/status only. | H2C/A2L, multi-nozzle, and per-extruder editing are excluded. |

## Recommended Architecture And State Lifetime

Add `ProcessSettingsPresentationModel` under `src/qml_gui/Models/` and expose
one instance from `ConfigViewModel`. It is a Process-only `QAbstractListModel`
that owns presentation inputs (`activePage`, `searchText`, `advancedMode`) and
the session collapse-key set, but holds no copied option values or preset data.
It consumes the existing `ConfigViewModel::filterOptionIndices("print", ...)`,
narrows to the active page, partitions by the ordered manifest, applies
temporary search reveal, and emits flattened `group` and `option` rows.

The model must rebuild when its inputs change and when option-model values,
references, read-only state, schema mapping, or viewmodel/preset state changes.
It must not keep stale integer indices after a preset change. Suggested roles:
`rowKind`, `page`, `group`, `optionIndex`, `collapsed`,
`forcedExpandedForSearch`, `matchingOptionCount`, `totalOptionCount`,
`matchingDirtyCount`, and `totalDirtyCount`.

`SettingsDialog.qml` selects this model only for `presetTier == "print"` and
renders a `ProcessGroupHeader` plus existing `OptionRow` delegates. QML forwards
semantic commands only. `OptionRow.qml` receives Process-only opt-in properties
for reset, validation, source, vector, and compact status presentation; its
existing printer/material consumers stay on their current path. Do not put a
`collapsedGroups` map, filter arithmetic, or copied values in QML.

## Requirements-Ready Feature Categories

1. **Source-correct Process navigation**: exact upstream page/group/order
   manifest; auditable key membership; page-qualified visible and dirty counts;
   no empty stale-key tabs.
2. **Real group disclosure**: full-row clickable and keyboard-focusable header;
   truthful chevron/accessibility state; independent collapse per page/group;
   preserved session state and temporary search reveal.
3. **Stable filtering and mode behavior**: one C++ projection; query retained
   through page/mode changes; Advanced strictly includes Simple; no stale rows
   after edits, preset operations, or reference/readonly refresh.
4. **Dense typed Process rows**: stable label/value/meta columns; sidetext before
   fallback unit; tooltip, dirty/source/inheritance/read-only/nullability state;
   per-option reset only when writable and dirty; group reset only when its
   page-qualified group is dirty.
5. **Safe value and availability feedback**: backend read-only protection and
   supported type/bounds/enum validation; no fake two-value range editor from
   schema min/max; honest scalar vector status; source-mapped dependency
   explanation where implemented.
6. **Preset feedback and regression evidence**: readable dirty, compatible,
   incompatible, and read-only/Save As state; upstream-compatible preset policy
   without dropping the current incompatible selection; guarded save/switch/close
   flow remains intact; automated and visual workflow proof.

## Suggested Build Order

1. Freeze and test the ordered Process page/group/key manifest against
   `TabPrint::build()`. Correct `kPrintPageGroupMap`, `pageNames()`, and related
   order/count APIs before changing any QML.
2. Implement and unit-test `ProcessSettingsPresentationModel`: page/query/mode
   inputs, page-qualified collapse keys, deterministic flattened rows, accurate
   count semantics, notification rebuilds, and search temporary reveal.
3. Expose the presentation model from `ConfigViewModel`; connect source and
   preset signals; make group reset page-qualified; enforce backend read-only
   protection and schema validation results.
4. Replace only the Process branch of `SettingsDialog.qml` with source-derived
   tabs and projection delegates. Add `ProcessGroupHeader.qml`; remove the
   decorative Process header path, but preserve non-Process behavior.
5. Harden Process-only `OptionRow` presentation and preset feedback. Fix the
   misleading range branch, expose reset/validation/source/vector limits, and
   retain all writes through the existing C++ chain.
6. Replace obsolete token-only QML audits with behavior tests, then run targeted
   tests, full CTest, the canonical build command, and deep-link visual checks
   with `--skip-first-run --open-dialog settings:process`.

## Non-Goals

- Printer or material feature expansion, hierarchy changes, or workflow redesign.
- H2C/A2L, multi-nozzle, AMS, per-extruder, or full vector-value editing.
- Device, hardware, network, cloud, camera, or monitor behavior.
- SLA settings or slicing, `libslic3r` algorithm changes, or unmapped product
  behavior.
- A second option/preset service, QML business-rule duplication, `QSettings`
  accordion persistence, or re-registering `GroupNavSidebar.qml`.
- Broad upstream cross-option correction logic without a separately recorded
  source mapping and behavior test.

## Risks And Prevention

| Risk | Prevention and proof |
|---|---|
| Decorative header is made clickable but grouping remains flat and unstable. | Render only model-projected header/option rows; test zero/one/many row groups across query, page, and mode changes. |
| Order or membership drifts from OrcaSlicer. | Maintain one ordered `TabPrint::build()` manifest; fail tests for unknown, duplicate, reordered, or fallback-mapped Process keys. |
| Collapse state is lost, localized, or leaks to other tiers. | C++ session model keyed by technical page/group IDs; test the complete persistence matrix and never write it to preset/project settings. |
| Preset or option refresh leaves stale delegates/counts. | Rebuild on model/viewmodel revisions; test edit, reset, discard, Save As, preset switch, read-only change, and mode refresh without reopening. |
| UI polish corrupts config semantics. | Reject read-only mutation in C++; validate supported typed values in C++; route every write/reset through `ConfigViewModel`; assert dirty/source/compatibility and slice invalidation. |
| Range/vector affordances overclaim capability. | Remove schema-bound-as-value presentation; test real scalar/enum/string/nullability behavior and assert excluded multi-extruder controls are absent. |
| Dense layout clips or hides state. | Use constrained grid tracks, full-row header hit targets, icons with localized accessible labels/tooltips, and visual checks at fixed size, higher scale, long labels, long units, dirty/read-only/source combinations. |
| Evidence proves source tokens rather than user behavior. | Add model, QML interaction, E2E, and deterministic visual coverage for collapse, filtered reveal, Advanced, reset, compatibility, and dirty/save flows. |

## Verification Baseline

Extend `tests/ViewModelSmokeTests.cpp` for hierarchy order/membership, duplicate
group identity, filtering, collapse lifecycle, counts, validation, and reset.
Extend `tests/QmlUiAuditTests.cpp` to require the Process projection and an
interactive header while ensuring `GroupNavSidebar.qml` remains absent from the
resource file. Extend relevant `tests/E2EWorkflowTests.cpp` cases so an expanded
Process edit still invalidates slicing and dirty/save/discard/Save As behavior
survives navigation. Complete with visual inspection of source-derived tabs,
collapsed and filtered groups, Simple/Advanced modes, long row metadata,
read-only and dirty states, reset, and compatibility feedback at the established
Process dialog fixture size.

**Confidence:** High for hierarchy, current data paths, and regression seams.
Medium for final visual composition and any dependency/availability rule not yet
mapped from `ConfigManipulation`. Those rules require source-to-Qt mapping before
implementation, not a QML approximation.
