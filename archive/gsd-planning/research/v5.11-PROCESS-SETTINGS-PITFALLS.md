# Process Settings Pitfalls

**Domain:** v5.11 Process Settings Source-Truth Convergence
**Researched:** 2026-08-03
**Confidence:** HIGH for current-code risks; MEDIUM for the exact upstream collapse interaction, which must be recorded before implementation.

## Critical Pitfalls

### Pitfall 1: Treating the decorative header as an isolated QML icon fix

**What goes wrong:** Replacing `+` with a clickable glyph only changes the first row that happens to start a group. The current `SettingsDialog.qml` derives headers from adjacent entries in `filteredIndices`, so hidden rows, a search result, or a tab change can leave orphan headers, rows from a collapsed group, or a wrong count.

**Why it happens:** The process dialog currently owns a flat `QList<int>` cache, and `OptionRow.qml` receives only `showGroupHeader` and a group string. There is no first-class group projection, group identity, or expansion state.

**Consequences:** Collapse can appear to work for an unfiltered page but fail after search, advanced-mode changes, model refresh, or a preset switch. A user can mistake a partial search result for the full group.

**Prevention:** Make the C++ process-settings projection emit ordered group records with stable source keys, visible-option counts, dirty-option counts, and a group expansion state keyed by the upstream page plus group identity. Derive all displayed rows from that projection after page, search, and mode filtering. Do not let a delegate decide group boundaries by reading its predecessor.

**Detection:** Test a group with zero, one, and multiple visible rows across page changes, a matching search, a non-matching search, and simple-to-advanced mode changes. Assert no duplicate or orphan header and no row from a collapsed group.

**Likely phase:** Process navigation and group projection.

### Pitfall 2: Losing source order or silently moving options between pages

**What goes wrong:** A navigation model based on `ConfigOptionModel::groupNames()` presents alphabetically sorted group names, while the rendered list currently inherits model insertion order. The schema also has a hard-coded key-to-page/group map as a fallback. Either source can diverge from the upstream `TabPrint::build()` `add_options_page()` and `new_optgroup()` order.

**Why it happens:** Group names are collected in a `QSet` then sorted, while page/group metadata comes from an incomplete schema mapping rather than a single ordered upstream-derived structure.

**Consequences:** The page tree, group header sequence, search path, count badges, and reset target can disagree. An option not present in the key map can fall into `Other`, hiding a migration gap behind a plausible UI.

**Prevention:** Keep an ordered process page/group catalogue derived and validated against `third_party/OrcaSlicer/src/slic3r/GUI/Tab.cpp` (`TabPrint::build()`). Use stable untranslated IDs for identity and translated labels only for presentation. Make unknown or duplicate mappings a test failure or an explicit documented gap, never an implicit alphabetical fallback.

**Detection:** Add an audit fixture that compares the Qt catalogue page/group order and known option membership to the recorded upstream mapping. Verify visible and dirty counts use the same filtered ordered projection.

**Likely phase:** Source mapping and process navigation.

### Pitfall 3: Collapsed state is reset, leaked, or applied at the wrong scope

**What goes wrong:** State held in a delegate is destroyed while scrolling; state held only in `SettingsDialog.qml` resets when the window is reopened; state keyed by a translated title changes with locale. Conversely, globally persisted state can leak between printer, material, and process dialogs.

**Why it happens:** The current dialog has no group-state owner. It creates only `activeTab`, `searchText`, `advancedMode`, and a flat filtered-index cache.

**Consequences:** The requested preservation across tab, search, and advanced-mode changes cannot be guaranteed. Reset/discard/preset changes may leave a collapsed section visually stale or apply its state to an unrelated group.

**Prevention:** Define and test one lifecycle contract before coding: expansion is keyed by process page/group IDs, survives filter and mode recomputation, and is reconciled when the source group set changes. Keep it scoped to the process dialog/session unless an upstream persistence source is identified. A search must define whether it temporarily exposes matched rows without mutating stored expansion state; record the upstream evidence for that rule.

**Detection:** Exercise collapse, search, clear search, toggle mode, switch tabs, reset a group, discard changes, save-as, change a compatible preset, close, and reopen. Assert the defined persistence matrix exactly.

**Likely phase:** Group interaction state and lifecycle.

### Pitfall 4: Using stale filtered delegates after a model or preset change

**What goes wrong:** The list retains old numeric rows or headers after values, readonly keys, reference values, option visibility, or the active preset changes.

**Why it happens:** `rebuildFilter()` is triggered only by `searchText`, `advancedMode`, and `activeTab`. `ConfigOptionModel` emits `dataChanged` and `dataVersionChanged` from `applyValues`, `setReferenceValues`, and `setReadonlyKeys`, but the QML filtered-index cache has no binding to either notification.

**Consequences:** The page can show stale dirty badges, stale compatibility/source labels, hidden-in-mode options, or invalid group counts after the viewmodel applies the new scope/preset configuration.

**Prevention:** Put filtering and grouping behind a C++ observable projection, or make the dialog rebuild from an explicit model/viewmodel revision signal that covers values, mode visibility metadata, group/page metadata, preset selection, and readonly/reference changes. Preserve list position by stable group/key identity, not an old row number.

**Detection:** With a live dialog, mutate an option, choose another preset, discard, reset, change scope/readonly state, and alter mode-dependent visibility. Assert delegates, counts, source badges, and enabled state refresh without reopening the dialog.

**Likely phase:** Projection notification contract.

### Pitfall 5: Breaking dirty, source, reset, and compatibility semantics while improving presentation

**What goes wrong:** A per-option or per-group reset changes only the display value, marks the wrong dirty state, or resets to defaults when upstream semantics require the current reference/inheritance level. A UI-only source badge becomes inconsistent with `valueSources_`. Saving a read-only preset or switching a preset bypasses the existing unsaved-change guard.

**Why it happens:** `ConfigOptionModel::resetOption()` uses reference values when present, while `ConfigViewModel` owns the active tier, merged preset hierarchy, dirty guard, compatibility message, and save-as flow. `OptionRow.qml` has no reset control today despite a comment stating reset is per group.

**Consequences:** Users can lose changes, see incorrect dirty counts, edit a read-only item, or assume a reset removed an override when the backend hierarchy still contains one. Slice invalidation can be missed.

**Prevention:** Route every edit and reset through `ConfigViewModel` and the option model; never mutate a QML display property. Define each reset affordance against the existing `resetOption`, `resetGroup`, and `resetOptionToLevel` contracts, then update merged values, reference values, dirty state, compatibility feedback, and slice invalidation as one operation. Keep read-only save routed to Save As and preserve the pending-action guard.

**Detection:** Cover editable and read-only process presets, inherited/default/process source levels, a dirty group with mixed values, reset-to-reference, reset-to-level, discard, save, save-as, and preset switch. Assert `isPresetDirty`, per-group dirty count, value source, persisted merged values, compatibility state, and slice invalidation.

**Likely phase:** Preset and option-semantic integration.

### Pitfall 6: QML control behavior corrupts typed or vector option values

**What goes wrong:** A range editor changes the displayed maximum instead of a second data value; numeric rounding loses precision; enum index is assumed to equal upstream enum value; string edits update on every keystroke; vector/nullable options are represented by a decorative badge instead of an editable source-truth control.

**Why it happens:** `OptionRow.qml` uses key-name heuristics for range controls and maps several upstream types to a small generic set. Its current range maximum is bound to `oMax`, which is option metadata, and the row exposes only a one-value `setValue` route. `isVector` and `nullable` currently render as compact badges.

**Consequences:** Data corruption, invalid configurations, lost per-index values, excess slice invalidation, and a misleading claim of vector/inheritance support. Multi-nozzle/per-extruder UI remains explicitly outside v5.11.

**Prevention:** Restrict v5.11 to process option types and affordances proven by the upstream mapping. Use typed metadata and explicit index-aware APIs for every supported complex value; render unsupported in-scope metadata honestly without inventing per-extruder UI. Commit text/numeric values only through validated backend calls, preserve upstream enum values, and use source-provided units instead of key heuristics.

**Detection:** Unit-test scalar, enum with nontrivial values, nullable, string, percent/float precision, and every supported vector shape. Include invalid input, focus loss, Escape, and no-op edit cases. Assert unsupported H2C/A2L/per-extruder controls are absent.

**Likely phase:** Typed rows and validation.

## Moderate Pitfalls

### Pitfall 7: Visual density changes create clipping, overlap, or unusable inputs

**What goes wrong:** Fixed compact widths for label, metadata, and control columns exceed the 736 px dialog at translation, scale, or a long preset/source string. Text elides silently, tooltips obscure controls, or a header hit target conflicts with list scrolling.

**Prevention:** Use a stable header button with a full-row accessible hit target, a stateful chevron icon, and keyboard focus. Constrain row grids with minimum and maximum tracks; test the minimum dialog size, higher UI scale, long labels, long units, read-only/source/dirty combinations, and empty groups. Do not add nested cards or text buttons when the existing Cx icon/control conventions cover the action.

**Likely phase:** Process visual polish.

### Pitfall 8: Localization and accessible semantics lag behind new stateful UI

**What goes wrong:** Group labels are used as persistence keys, '+' and badge abbreviations carry the only meaning, tooltips are untranslated, or the expanded/collapsed state is invisible to keyboard and assistive users.

**Prevention:** Persist only stable nonlocalized IDs. Put every new user-visible label and tooltip through `qsTr()`, use recognizable expand/collapse icons with accessible name/state where supported, and supplement abbreviated badges with localized tooltips. Update translations through the existing i18n workflow, not ad-hoc literals.

**Likely phase:** Process visual polish and i18n validation.

### Pitfall 9: Evidence proves tokens exist but not that the workflow works

**What goes wrong:** Existing `QmlUiAuditTests` mostly assert source tokens such as `sectionGlyph`, Cx controls, and the flat-header wiring. Existing E2E coverage proves one setting invalidates a slice and a merged config round-trips, but does not exercise group collapse, filtered group construction, mode visibility, or reset state.

**Prevention:** Replace obsolete decorative-header token tests with behavioral model tests and QML interaction tests. Add deterministic screenshot/runtime captures using the established settings deep link for simple and advanced mode, a filtered view, a dirty group, a readonly preset, and a collapsed group. Run the canonical build and the relevant CTest set; record any visual-capture limitation explicitly.

**Likely phase:** Verification and regression lock.

## Phase-Specific Warnings

| Phase topic | Likely pitfall | Mitigation |
|---|---|---|
| Source mapping and group projection | Alphabetical or fallback mapping drifts from upstream order. | Freeze an ordered page/group/key mapping from `TabPrint::build()` and audit it. |
| Expansion state | Filters or translated labels invalidate stored state. | Key state by stable process page/group IDs and define the persistence matrix. |
| Model notifications | QML keeps stale `filteredIndices` after preset/model updates. | Expose one observable projection/revision and rebuild by stable identities. |
| Typed option rows | Range/vector/enum shortcuts corrupt values or imply excluded multi-extruder support. | Use backend typed APIs and limit affordances to recorded in-scope source truth. |
| Preset semantics | Reset/save/switch bypasses dirty, hierarchy, or compatibility behavior. | Reuse `ConfigViewModel` transaction paths and test end-to-end state. |
| Visual and regression evidence | Static source tests bless a nonfunctional control. | Add interaction, model, and screenshot evidence; remove obsolete decorative-header expectations. |
