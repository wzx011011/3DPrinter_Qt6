# Architecture Patterns: v5.11 Process Settings Source-Truth Convergence

**Domain:** OWzx Process (Print) settings editor
**Researched:** 2026-08-03
**Confidence:** HIGH for current code paths and upstream behavior; MEDIUM for the final visual composition because screenshot evidence is outside this research task.

## Recommended Architecture

Keep the current three-layer ownership and add a Process-only C++ presentation model. Do not make the shared `SettingsDialog.qml` calculate group membership, collapse state, counts, or visibility. QML should render a model already flattened into group-header and option rows, then send semantic commands back to C++.

```text
OrcaSlicer TabPrint::build / print_config_def
        |
        v
ConfigOptionModel
  schema metadata: key, page, group, mode, unit, tooltip, flags, dirty
        |
        +--> ConfigViewModel owns preset/scope values, source chain, save guards,
        |    compatibility, reset, and slice invalidation
        |
        v
NEW ProcessSettingsPresentationModel (Process tier only)
  active page + query + advanced flag + collapsed group keys
  ordered visible header/option rows and count roles
        |
        v
SettingsDialog.qml / NEW ProcessGroupHeader.qml / OptionRow.qml
  presentation and event forwarding only
```

This matches the existing composition root: `BackendContext` exposes `ConfigViewModel`, `main.qml` owns the one permanent `processSettingsDialog` instance, and the dialog uses `ConfigOptionModel` through the viewmodel. Existing edits already flow `OptionRow -> ConfigOptionModel::setValue -> ConfigViewModel::handleOptionValueChanged -> sliceAffectingConfigChanged`; v5.11 must preserve that chain.

## Current-State Findings

- `SettingsDialog.qml` owns `activeTab`, `searchText`, `advancedMode`, and a flat `filteredIndices` list. It calls `ConfigViewModel::filterOptionIndices`, then `ConfigOptionModel::filterIndicesByPage`. It does not consume a group navigation component.
- The dialog infers group headers from adjacent items in the flat list. `OptionRow.qml` renders a literal `+` in `sectionGlyph`, but that item has no handler, state, or effect on the list. This is the reported broken control.
- `GroupNavSidebar.qml` exists on disk but is intentionally absent from `qml.qrc`; `QmlUiAuditTests::v52ComponentCoherence` locks that historical orphan removal. Do not re-register or revive it for this milestone.
- `ConfigOptionModel` already exposes page, group, upstream mode, read-only, dirty, tooltip, sidetext, nullable, and vector metadata. It also supplies page/group filtering and per-group dirty counts. Its `groupNames()` sorts names alphabetically, so it is not sufficient for upstream display order.
- `ConfigViewModel::filterOptionIndices` owns case-insensitive/fuzzy search and Simple versus Advanced/Develop visibility. Its current rule is correct: advanced mode is a superset of simple mode. `ConfigViewModel` already owns per-group reset, save/save-as guard, dirty state, compatibility state, and slice invalidation.
- `PresetServiceMock` persists selected preset names in `QSettings`; it does not persist option-editor view state. Preset values are kept in memory and saved through the existing preset service APIs.

## Upstream Alignment

`TabPrint::build` is the truth for the Process page-to-group-to-option hierarchy. `ConfigOptionModel::loadFromUpstreamSchema` already imports `print_config_def`, then overlays `kPrintPageGroupMap` after loading its selected key list. v5.11 should complete and test that mapping from the locked upstream `Tab.cpp`, rather than introduce QML category maps or labels.

Relevant upstream semantics:

- `Page` owns ordered `ConfigOptionsGroup` instances; `Page::activate` and `Page::update_visibility` evaluate each group against `ConfigOptionMode`.
- `Tab::update_mode` calls `update_visibility` and rebuilds the page tree. `Tab::update_changed_tree_ui` derives modified/system state from option data, not from presentation widgets.
- `Tab::apply_searcher` delegates search to the application searcher using the active config, preset type, and mode. `Tab::activate_option` selects the correct page and focuses the option.
- `Tab::set_expanded` expands/collapses tab chrome, not an individual `ConfigOptionsGroup`. Therefore Process group collapse is permitted as local Qt UI state, but must never alter preset data, option mode, saved visibility rules, or slicing behavior.

The Process editor should retain its local current-page search behavior for this milestone: filter by query and mode first, then narrow to the active Process page, then group the surviving rows in upstream order. Do not silently turn it into global cross-page search. A future search-result navigator may explicitly follow upstream `activate_option` behavior.

## Presentation Model Contract

Create `ProcessSettingsPresentationModel` under `src/qml_gui/Models/` and construct it in `ConfigViewModel`; add it as a `CONSTANT` QObject property such as `processSettingsPresentation`. Add its `.h/.cpp` to the existing CMake Qt target.

The model should contain no copied configuration values. It holds a pointer to the existing `ConfigOptionModel` and uses `ConfigViewModel::filterOptionIndices("print", query, advanced)` as the single search/mode authority. It then calls the source model's page metadata and partitions the resulting indices in first-seen upstream order.

Suggested inputs and commands:

```cpp
Q_PROPERTY(QString activePage READ activePage WRITE setActivePage NOTIFY presentationChanged)
Q_PROPERTY(QString searchText READ searchText WRITE setSearchText NOTIFY presentationChanged)
Q_PROPERTY(bool advancedMode READ advancedMode WRITE setAdvancedMode NOTIFY presentationChanged)
Q_PROPERTY(QStringList pageNames READ pageNames NOTIFY presentationChanged)

Q_INVOKABLE void toggleGroup(const QString &page, const QString &group);
Q_INVOKABLE bool isGroupCollapsed(const QString &page, const QString &group) const;
Q_INVOKABLE void resetGroup(const QString &group);
```

Suggested row roles:

```text
rowKind: "group" | "option"
page, group, optionIndex
collapsed, forcedExpandedForSearch
matchingOptionCount, totalOptionCount
matchingDirtyCount, totalDirtyCount
```

The flattened rows must be rebuilt on input changes and on `ConfigOptionModel::dataChanged`, model reset, or `ConfigViewModel::stateChanged`. Collapse keys must use a stable technical identity such as `page + U+001F + group`, never translated display text alone.

### Collapse Rules

1. A collapse action mutates only the presentation model's `QSet` of Process page/group keys and emits `dataChanged` or resets the row model.
2. Switching page, changing query, or toggling Advanced mode rebuilds rows but never clears that set. A dialog hide/show also preserves it because `main.qml` owns one dialog instance and the viewmodel outlives it.
3. While a non-empty search has matching options in a collapsed group, the presentation model may expose those options with `forcedExpandedForSearch = true`; it must not mutate the stored collapsed bit. Clearing search restores the user's collapse choice.
4. Do not write collapse state to the preset, project, 3MF, or `PresetServiceMock`. Session-only state meets the stated preservation requirement without creating an undocumented product preference. Persisting it to `QSettings` can be a later, explicitly approved UX decision.

This keeps a click from being a QML business rule: QML invokes `toggleGroup`, C++ decides rows/counts, and only C++ owns the state transition.

## Filter And Count Semantics

Use one deterministic pipeline:

```text
source Process rows
  -> ConfigViewModel search and Simple/Advanced visibility
  -> active Process page
  -> ordered group partition
  -> collapse or temporary search reveal
  -> flattened render rows
```

- Search compares the label and technical key through the existing C++ exact/fuzzy rules. It does not mutate the query, page, active preset, or collapse map.
- Simple mode includes only mode `0`; Advanced includes `0`, `1`, and `2`. New code must not create a second QML interpretation of those numbers.
- `matchingOptionCount` is the count after query, mode, and page filters but before collapse. `totalOptionCount` is the group count in the active page independent of the query and mode. `totalDirtyCount` is all dirty options in that page/group; `matchingDirtyCount` is dirty options surviving the current filters. Expose both so the visual design does not accidentally lie when a dirty advanced option is hidden in Simple mode.
- Only nonempty matching groups appear during an active query. With an empty query, pages show their normal nonempty Process groups in upstream order.

## Option-Row State And Safe Edits

`OptionRow.qml` already receives typed values, units, source labels, read-only flags, dirty flags, nullable/vector flags, and tooltips. Retain those data sources. Make Process-only visual refinements opt-in, for example `processPresentation: presetTier == "print"`, so printer/material dialogs and the Prepare sidebar are not inadvertently redesigned.

Required implementation cautions:

- Add an explicit per-option reset action only when it calls the C++ reset path. For the current model this means reset to its current reference/saved value and then normal `handleOptionValueChanged` propagation; it must update dirty state and invalidate slicing through existing signals.
- `ConfigOptionModel::setValue` currently does not reject a read-only row; the UI merely disables its controls. Add a model-level read-only guard before adding more reset/value affordances.
- Current numeric conversion and range detection live in QML. Move validation/clamping decisions to C++ where feasible, expose a validation message/state role, and keep QML as a renderer. Do not present schema `min`/`max` bounds as two independently editable values: the current range branch displays the schema maximum as an editor value, which is not a paired config value.
- `isVector` currently records upstream vector metadata while `extractDefault` surfaces one value. Multi-nozzle/vector editing is explicitly out of scope. Show an honest active-value/vector status and tooltip, not a fake multi-entry editor. A real per-extruder editor requires preserving full vector values and an explicit nozzle-selection contract in a later milestone.
- `nullable` is metadata only today. Do not label the existing `resetOption` action as "drop inherited override" until the preset layer can distinguish raw local overrides from resolved effective values. `PresetServiceMock` currently stores resolved vendor values in one map, so true upstream override removal needs a separate raw/effective-value contract and is out of this scoped UI convergence.

## Preset Feedback Path

No new preset service is necessary. Reuse these existing authorities:

```text
Preset selector -> requestCurrentPrintPreset
  -> queue pending action if dirty
  -> UnsavedChangesDialog save/discard/cancel
  -> setCurrentPrintPreset + mergePresetHierarchy
  -> refresh option references and presentation rows

Save -> requestSavePendingChanges
  -> read-only preset emits saveAsRequired
  -> SettingsDialog opens SavePresetDialog

Compatibility marker -> currentPresetCombinationValid /
                        currentPresetCompatibilityMessage
```

The Process preset bar should make the existing dirty, read-only/save-as, and compatibility states legible, but should not call `PresetServiceMock` directly. Preserve `ConfigViewModel` as the single QML-facing action boundary.

## Anti-Patterns To Avoid

### QML-Owned Collapse Map

Do not add `property var collapsedGroups` plus inline filtering in `SettingsDialog.qml`. It will diverge from counts, bypass tests, and is lost or reordered when delegates rebuild.

### Alphabetical Or Translated Group Identity

Do not use `groupNames()` for Process display order or store translated labels as identity. Preserve upstream construction order and key collapse state by technical page/group identity.

### Fake Vector Or Inheritance Controls

Do not make a badge look editable when the backend only has a scalar projection of a vector, and do not claim a reset removes a local inherited override when the current preset store cannot model that distinction.

### Shared Dialog Regression

Do not convert the shared dialog wholesale. The milestone is Process only; printer and material must continue using their existing model/filter branch until separately scoped.
