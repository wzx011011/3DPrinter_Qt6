# Feature Landscape: v5.11 Process Settings Source-Truth Convergence

**Domain:** FFF Process preset editor in OWzx Slicer
**Researched:** 2026-08-03
**Confidence:** HIGH for the current code and locked OrcaSlicer source; MEDIUM for screenshot-only visual details because no Process-dialog reference screenshot is in `shotScreen/`.

## Scope

This milestone makes only the `print` tier of `SettingsDialog` a dependable
parameter-editing workspace. It must retain the shared dialog shell where that
helps, but it must not turn printer or filament editing into v5.11 work.

The project requires durable behavior in C++ and QML to remain presentation and
wiring (`.planning/PROJECT.md:285-290`). The source of truth is the locked
OrcaSlicer `TabPrint`, `Tab`, `PresetComboBoxes`, and `ConfigManipulation`
behavior, with screenshot density treated as layout truth.

## Executive Conclusion

The core Process option data is substantially stronger than the current UI.
`ConfigOptionModel` already loads upstream schema metadata, maps options to
Process pages/groups, exposes dirty/reference/read-only/nullable/vector/unit
information, and can count and filter groups. `ConfigViewModel` also has dirty
guards, save-as routing, compatibility diagnostics, search/mode filtering, and
group reset primitives. Smoke tests exercise much of that data surface.

The current Process dialog does not compose those capabilities into a complete
editor. It renders a flat filtered list and inserts a header when the group
changes. That header contains a literal `+` with no input handler or collapsed
state. The old `GroupNavSidebar` is present on disk but is deliberately absent
from the QML resource and the dialog. Worse, the hard-coded Process tab array
does not match the upstream page keys: it omits `Multimaterial`, uses `Base`,
`Cooling`, and `Retraction` as pages although the schema places the latter two
under `Others`, and uses `Other` rather than upstream `Others`. These tabs can
produce empty content or hide mapped options.

The milestone should therefore be measured as a user workflow, not as a
component polish pass: select the real Process page/group, expand it, find an
option through search or Advanced mode, understand its effective value and
state, edit or reset it safely, and see truthful dirty/compatibility feedback.

## Missing or Incorrect Behavior

1. Group expansion/collapse is entirely cosmetic. It is the direct cause of the
   reported broken `+` control.

2. The Process page array is not source-derived. `Base`, `Cooling`,
   `Retraction`, and singular `Other` conflict with the current upstream
   `TabPrint::build` and with `kPrintPageGroupMap`; `Multimaterial` is absent.
   This is a functional navigation defect, not merely a label issue.

3. Group data is split from the dialog: `GroupNavSidebar` has selection/count
   wiring but no dirty count and no active consumer. Its previous orphan-removal
   test must be replaced when a process-only navigation surface is restored.

4. The filtering chain cannot direct a result to another page/group, and no
   collapsed-group search policy exists. The comment in the smoke test describes
   a selected-group stage that the Process dialog no longer implements
   (`ViewModelSmokeTests.cpp:4409-4446`).

5. The row exposes state badges but does not provide the corresponding reset or
   inheritance action. The range pair is semantically wrong, and no explicit
   validation/availability state exists.

6. Preset compatibility is real in the service but reduced to a small red
   marker in the Process dialog. The selector does not reflect the upstream
   compatible-by-default policy or present per-choice state.

## Explicit Non-Goals

| Non-goal | Rationale | Required boundary |
|---|---|---|
| Printer and filament feature expansion | v5.11 optimizes only the Process editor. Shared controls may be hardened only when Process uses them. | Do not add tier-specific pages, rules, or workflows outside Process. |
| H2C/A2L multi-nozzle and per-extruder editors | The project explicitly excludes multi-nozzle and per-extruder UI (`.planning/PROJECT.md:254`). | Show a truthful scalar/vector affordance only; do not add per-extruder lists, switching, or editing. |
| SLA settings or slicing | Permanently excluded in the milestone context. | Do not expose SLA pages or SLA validation paths. |
| Hardware, network, cloud, or printer-connected workflows | Removed product scope. | No device-dependent Process actions. |
| A new product-specific Process taxonomy | OrcaSlicer is functional truth. | Derive visible pages/groups from the locked source/schema; document any absent schema key instead of inventing a bucket. |
| QML business-rule duplication | The project architecture forbids durable behavior in QML. | Keep collapse/filter state presentation-facing, but place validation, availability, hierarchy derivation, and preset semantics in model/viewmodel APIs. |

## Feature Dependencies

```text
Upstream Process schema/page-group map
  -> canonical tabs and active-page group model
  -> visible counts and group navigation
  -> collapse state + tab/search/mode reconciliation
  -> screenshot and interaction regression coverage

Option state/availability model
  -> truthful row metadata and reset/inheritance actions
  -> validation/disabled explanations

Preset compatibility and dirty service state
  -> selector item state and top-level feedback
  -> guarded save/switch/close behavior
```

## MVP Recommendation

Prioritize the following in roadmap order:

1. Canonicalize Process hierarchy and filtered navigation. Derive tabs/groups
   from the Process model and replace the invalid hard-coded tab keys.
2. Make group disclosure real and reconcile it with page, search, and Advanced
   state. Add visible/dirty counts only after the filter-state contract is
   deterministic.
3. Close option-row truthfulness: reset/reference action, source/inheritance
   explanation, valid compound handling, vector limitation affordance, and
   compact visual polish.
4. Connect Process availability/validation data to the upstream FFF rule
   matrix, then upgrade preset dirty/compatibility feedback and selector policy.
5. Add behavior tests plus Process dialog visual evidence for the complete
   workflow; replace contradictory orphan-removal assertions.

Defer all multi-nozzle value editing even though vector metadata is visible.
The first scalar component may remain readable for a single-nozzle workflow,
but the UI must not claim it represents an editable per-extruder vector.

## Testable Capability Set

- A Process dialog opened on each source-derived page contains only mapped
  groups/options; no tab is empty solely because it uses a stale key.
- A user can collapse one group, edit another, switch tabs, search, toggle
  Advanced, clear search, and return to the original group state.
- Searching for a Process option on another page offers a route to its page and
  opens/reveals its group before focus is applied, matching upstream
  `Tab::activate_option` intent.
- Group visible and dirty counts equal the final filtered row set and change
  after edit/reset/mode/search operations.
- A dirty row can reset to its effective reference; a group reset clears only
  that group's dirty options. Read-only and inherited state are not represented
  as the same disabled appearance.
- A range/value pair round-trips the actual source values. A vector option is
  explicitly limited to the supported single-nozzle representation.
- A dependency update changes availability/validation feedback immediately and
  retains the user value unless upstream behavior changes it.
- Dirty, compatible, incompatible, read-only, Save As, discard, cancel, and
  close-guard paths remain accurate after navigation/filter interactions.
